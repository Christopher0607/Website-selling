# 06 — 客户交付流程（SOP）

> 从签约到上线到月费维护，每个客户都照这个流程走。客户代号：`c001`、`c002`…
> 每个客户的检查结果记录在 `clients/<代号>/checklist.md`（复制本文件最后的「上线检查清单」）。

---

## 阶段 0：签约前

- [ ] 客户接受报价（`templates/proposal.md`）
- [ ] 合同签好
- [ ] 收到 50% 订金
- [ ] 在 `sales/prospects.csv` 把状态改成 `won`

---

## 阶段 1：开工（第 1 天）

- **Claude Code：** 建客户档案 `clients/<代号>/`（任务 6.1）
- **俊宇：**
  1. 发欢迎信息（04 §4.7）+ 资料表。资料表可以把 `templates/client-brief.md` 的问题做成 Google 表单，或存成 PDF 给客户填
  2. 开一个 WhatsApp 群组（客户 + 你），说明回复时间
  3. 约 30 分钟开工通话（可选）：确认目标、风格、上线日期

---

## 阶段 2：资料检查（第 2–5 天）

- [ ] Logo（SVG 或高解析 PNG，透明背景）
- [ ] 品牌颜色（没有的话从 logo 取色）
- [ ] 产品资料：名称、价格、规格 / 变体、重量（算运费用）、库存、描述。客户能从 Shopee 卖家中心下载产品资料表的话，Claude Code 可以写脚本转成 WooCommerce 导入格式
- [ ] 产品照片（每款至少 1 张，背景尽量一致）
- [ ] 关于我们 / 品牌故事
- [ ] 政策：运费、送货时间、退换货
- [ ] 公司资料：SSM 名称和号码、地址、电邮、电话
- [ ] 付款网关：**客户用自己的公司名义申请**（我们协助），拿到测试 Key 和正式 Key
- [ ] 域名：客户已有的（给 DNS 管理权限），或用客户的名义新买
- [ ] WhatsApp 号码、社交链接
- [ ] 风格参考（2–3 个喜欢的网站）

**资料齐全那天开始算交付时间。** 在群组告诉客户预计交付日期。

---

## 阶段 3：建站（staging 测试站）

1. `clone-site.sh master staging-<代号> staging-<代号>.yourbrand.com --basic-auth --noindex`
2. 填好 `clients/<代号>/brand-config.json`（`mode` 设为 `staging`），执行 `apply-brand.sh`
3. 关闭 Demo 模式（测试站要能测下单）；付款网关接**测试模式**
4. 产品图片跑 `optimize-images.sh`，产品用 CSV 导入
5. 按客户资料填页面；法律页面用客户的资料取代 `[方括号]`，提醒客户请律师确认
6. 运费区、免运门槛、自取（如果有）
7. 邮件：FluentSMTP 的发件人改成客户的域名；列出 SPF / DKIM / DMARC 记录给客户或代客户加
8. 追踪（Growth 套餐）：GA4 + Meta Pixel 用**客户自己的账户**，把你加为管理员或合作伙伴
9. SEO：网站标题、描述、产品 SEO 标题
10. 记录在 `clients/<代号>/README.md`（格式同 02 §9）

---

## 阶段 4：内部检查

按本文件最后的「上线检查清单」A–E 先自己检查一次，**全部通过才给客户看**。

---

## 阶段 5：客户审核与修改

1. 发测试站链接 + 密码 + 3–5 分钟介绍视频（录屏讲重点）
2. 请客户**一次整理所有修改**（一条 WhatsApp 信息或一个文件），每项编号
3. 每一轮：确认修改清单 → 修改 → 逐项回复 "✅ 已改"
4. 超过套餐的修改轮数，或新的功能 → 先报价（加购）
5. 最后一轮：请客户书面确认"可以上线"（WhatsApp 也算）

---

## 阶段 6：上线前

- [ ] 「上线检查清单」A–G 全部通过
- [ ] 发余款通知，**收到余款才上线**
- [ ] 跟客户约上线时间（避开他的促销高峰）
- [ ] 提前 24–48 小时把客户域名 DNS 的 TTL 调低（例如 300 秒）

---

## 阶段 7：上线

1. 备份测试站（`backup-site.sh`）
2. 搬到生产服务器：测试站和正式站在不同服务器，用 `migrate-site.sh`（02 §7.16）
3. 客户域名的 DNS 改指到生产服务器，等生效
4. 申请 SSL
5. 关掉 basic auth 和 noindex（WordPress「阅读」设定允许搜索引擎；agency-core 的 `mode` 设为 `live`）
6. 付款网关切换到**正式 Key**
7. **真实小额测试订单：** 客户同意后，用最便宜的产品真的付款下一单 → 确认订单、邮件、钱到账 → 退款并取消订单
8. Search Console 验证 + 提交 sitemap（用客户的 Google 账户，或你建好后转给客户）
9. 加在线监控；确认备份已经成功跑过一次
10. `smoke-test.sh https://客户域名 --shop` PASS，而且**没有** noindex
11. 测试站：有月费的客户保留（用来测试大更新）；没有月费的 7 天后删除

---

## 阶段 8：交接

- **客户账号：** 给客户建「Shop manager」角色的账号（可以管产品和订单，不能改插件和设定）；你保留 Administrator
- **30 分钟线上教学（录下来给客户）：** 上新产品、改价格和库存、处理订单（出货、标记完成）、退款、改首页文字、看销售报表
- **交接文件**（`clients/<代号>/handover.md`，转成 PDF 给客户）：
  - 网站网址、后台登录网址、账号（密码用密码管理器分享，不要用 WhatsApp 发明文）
  - 付款网关、域名、GA4 / Meta 账户在哪里登录（客户自己保管）
  - 月费包含什么、怎么提出修改、回复时间、紧急联络方式
- **小建议：** 请客户在包裹里放一张小卡片，QR 码连到网站——帮他把回头客带到官网
- 上线当天问"用得顺吗？"；30 天后再正式请评价和介绍（04 §4.8）

---

## 阶段 9：上线后跟进

| 时间 | 做什么 |
|---|---|
| +3 天 | 确认订单、邮件、付款都正常 |
| +7 天 | 问客户有没有问题；看 GA4 和订单是否正常 |
| +30 天 | 小检讨（订单、问题、建议）；请评价和介绍；免费维护结束，开始收月费 |

---

## 阶段 10：月费维护

**每周（标准 Care）/ 每月（基础 Care）：**
- [ ] `site-inventory.sh` 看所有站的状态
- [ ] `update-site.sh`（大版本更新先在测试站测）
- [ ] `smoke-test.sh` PASS
- [ ] 确认备份成功（UpdraftPlus 记录 + 服务器备份）
- [ ] 看在线监控记录

**每月：**
- [ ] 处理修改请求，记录用了多少分钟
- [ ] 抽查 PageSpeed
- [ ] 发月报（`templates/monthly-report.md`）
- [ ] 收下个月的月费

**每季：**
- [ ] **还原测试**（还原到临时站，确认能用，再删掉）
- [ ] 检查管理员账号，删除不用的账号和 Application Password
- [ ] 检查域名、付款网关、付费插件的续费日期
- [ ] 给客户一个改进建议（例如活动页、SEO 文章）——这也是自然的加购机会

### 修改请求

1. 客户在 WhatsApp 提出 → 你确认内容和预计时间
2. 在 Care 时间以内就直接做；超过的话先报价
3. 记录在 `clients/<代号>/changes.md`（日期、需求、用时、完成日期）

### 紧急情况（网站挂掉 / 被入侵）

1. 先告诉客户你在处理
2. 看监控和错误日志找原因
3. 无法很快修好 → 还原最近一次正常的备份
4. 被入侵：换掉所有密码和 salts、更新所有东西、扫描、找出原因，写事故记录给客户
5. 如果可能有顾客资料外泄，提醒客户可能有通报义务，请他咨询律师

### 客户离开

- 免费提供完整备份（数据库 + 文件）；要我们帮忙搬到新主机，按「网站搬家」价格收费
- 交还所有账号权限；客户确认后删除你的管理员账号
- 你服务器上的站点：备份保留 30 天后删除

## 上线检查清单（复制到 `clients/<代号>/checklist.md`）

### A. 功能
- [ ] 首页、商店、分类、产品页正常
- [ ] 加入购物车、改数量、删除正常
- [ ] 结账：西马和东马地址的运费正确；免运门槛正确
- [ ] 测试付款成功；订单出现在后台；库存减少
- [ ] 顾客的订单邮件、店主的新订单邮件都进收件箱
- [ ] 忘记密码邮件收得到
- [ ] 联系表单、WhatsApp 按钮正常，预填信息正确
- [ ] 优惠码（如果有）正常
- [ ] 404 页面正常

### B. 手机与浏览器
- [ ] 手机（360 px）、平板、桌面版面正常
- [ ] Chrome（Android）和 Safari（iPhone）都测过
- [ ] 浮动按钮不挡住重要按钮

### C. 内容
- [ ] 没有占位文字（Lorem ipsum、`[方括号]`、示范产品）
- [ ] 错字检查（Claude Code 跑一次）
- [ ] 所有图片都有 alt 文字
- [ ] 价格、规格、库存跟客户资料一致
- [ ] 所有链接有效

### D. 合规（02 §4.5）
- [ ] 公司名称、注册号码、电邮、电话
- [ ] 完整价格，运费清楚
- [ ] 付款方式
- [ ] 条款与条件、运送与退换
- [ ] 隐私通知（马来文 + 英文）
- [ ] 客户已请律师确认法律页面，或书面表示自行负责

### E. 性能与 SEO
- [ ] PageSpeed 手机版 ≥ 80
- [ ] 网站标题、描述、网站图标
- [ ] sitemap 正常
- [ ] 正式站没有 noindex（测试站必须有）

### F. 安全与备份
- [ ] SSL 有效，http 跳转 https
- [ ] 管理员开 2FA、强密码、用户名不是 admin
- [ ] 不用的插件和主题已删除
- [ ] 备份已设定并成功跑过一次
- [ ] 在线监控已加入

### G. 交接
- [ ] 客户的 Shop manager 账号
- [ ] 教学视频
- [ ] 交接文件
- [ ] 付款网关、域名、GA4 / Meta 账户都在客户名下
